LFM3 Test Lab

Install, test and benchmark any LFM3 model with llama.cpp. Everything runs locally.

⚡ Quick Start (Windows PowerShell)

Step 1: Install the runtime

Install llama.cpp, then check you have a recent build — older ones do not know the LFM3 architecture:

winget install llama.cpp
# Mac: brew install llama.cpp
llama-cli --version

Step 2: Create a Python environment

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install requests

Step 3: Download & run the model

The balanced 4-bit Q4_K_M build is about 1.1 GB and is pulled straight from Hugging Face:

llama-cli -hf LiquidAI/LFM3-1.7B-GGUF:Q4_K_M
llama-server -hf LiquidAI/LFM3-1.7B-GGUF:Q4_K_M -c 32768 --port 8080

Step 4: Run the tests and the benchmark

python test_lfm3.py
python bench_lfm3.py

⚠ Known limits

  • Liquid says it is not recommended for agentic coding or complex multi-step reasoning.
  • Knowledge-heavy questions: add search or RAG.
  • Voice and omni models have a 32K-token context window.
  • Free commercial use only under $10M yearly revenue (LFM Open License).

Liquid AI just released LFM3, and it's not one model — it's a family of six small models.

Text, vision, audio, a full omni model, even decision models.

Every one is around 2 billion parameters, made to run on your laptop or even a phone.

In this video: install it, run it, test it on real tasks, then benchmark it on my own machine.

So you can see what is real and what is just marketing. Let's start.

First, a quick overview. LFM3 comes in six versions.

LFM3-1.7B: plain text — chat, RAG, tool calling, with up to 256K context.

LFM3-VL-2B handles images and video. LFM3-Audio-2B does speech in and out, in 18 languages.

LFM3-Omni-2B does text, vision and audio together in one model.

The d1 models are decision models that return structured output with probabilities.

All of them share the same 1.7B base — that's why the footprint is so small. The 4-bit text model is about 1.1 GB.

One important thing before business use: the LFM Open License is free for commercial use only under 10 million dollars yearly revenue.

Above that you need a paid license. Research and non-profit use is free. Don't skip this.

The process is the same for any LFM3 model. I'll show the text model first — then you just swap the model name.

For running you have two options. llama.cpp is the safest and works right now on Windows, Mac and Linux.

Ollama is easier, but support for the lfm3 architecture came a little later.

If your Ollama is old you will see this error: unknown model architecture lfm3. Don't panic.

Update Ollama, or just use llama.cpp. I'll use llama.cpp for the benchmark because it gives exact timing numbers.

Step one, install llama.cpp. On Windows, winget install llama.cpp. On Mac, brew install llama.cpp.

Important: you need a recent build, because older versions don't know the LFM3 architecture. Check with llama-cli --version.

Step two, create a clean Python environment for our test scripts, same as the last video.

Step three, download the model. llama.cpp can pull it straight from Hugging Face.

Q4_K_M is the sweet spot: about 1.1 GB and quality stays good. Going lower saves very little space.

If you see the prompt, the install is done.

For a different model — VL or Omni — only change the repo name. Everything else stays the same.

Before any big test, a simple sanity check. I'll ask: explain what a KV cache is in 3 lines for a beginner.

Let the answer stream. At the end, the speed line shows prompt speed and generation speed in tokens per second.

My speed is on screen now. We'll measure it properly in a few minutes.

One tip: thinking mode is on by default in this model, so you may see reasoning text first. That's normal.

Now let me start the model as a local server, so my script can talk to it.

I'm using a 32K context, because that is what Liquid used for their own speed tests — so our comparison is fair.

Three tests, one per ability, all run from one script: instruction following, tool calling, long context.

First test is instruction following. I give strict rules: exactly 3 bullets, each under 10 words, no emojis.

This is where LFM3 is supposed to be strong — the vendor reports an IFBench score around 73.

Let's see the real output, and count the bullets on camera.

Second test is tool calling, the main use case for small on-device models.

I define one tool, get_weather(city), and ask: what's the weather in Tirupati?

The model should not answer directly. It should return a tool call with the correct JSON.

Note: the tool-call format changed from the older LFM2, so if your old code breaks, this is why.

Third test is long context. I paste a long document and hide one fact in the middle.

Then I ask a question about it. This tells us if the model really uses its context, or only claims 256K.

I'll say clearly whether it found the fact.

If you're testing VL or Omni, add an image or audio file here — same as the tomato image task in my last video.

Honest note: llama.cpp support for vision and video is still maturing, so follow the model card for the runtime.

On these tests, my results are on screen.

And one thing to know: Liquid themselves say this model is not recommended for agentic coding or complex multi-step reasoning.

So I won't test that and pretend it's good.

Now the benchmark. Marketing numbers are one thing — I want to know speed on my machine.

This script sends the same prompt five times and records two things.

Prompt speed: how fast the model reads your input.

Generation speed: how fast it writes the answer. This is the number you feel as a user.

The first run is often slower because of warm-up, so drop it from the average.

My machine, average speeds and memory used are on screen now.

For memory, I watch nvidia-smi, Activity Monitor or Task Manager while it runs.

Now let's put my numbers next to what Liquid claims.

Remember, these are Liquid's own numbers — Q4_0, batch size 1, 32K context — not yet independently reproduced.

A 1.7B model beats a 9B model on instruction following and tool calling.

But the bigger model still wins on hard knowledge, coding and very long context.

So this is a specialist, not a replacement for a big model.

My numbers versus theirs depend on your hardware, quantization and background apps.

So, verdict. LFM3 wins on size, speed, instruction following, tool calling and long-context memory.

It doesn't win on hard reasoning, coding or knowledge-heavy questions — use search or RAG with it.

Voice and omni models only have 32K context, tooling is still new, and the license has a revenue limit.

Use it for local assistants, tool-calling agents, offline apps and edge devices — not as your main reasoning model.
